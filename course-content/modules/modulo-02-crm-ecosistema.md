## Antes de comenzar

Completa primero el Módulo 1 y conserva el proceso que priorizaste. En este módulo no conectarás herramientas ni trabajarás con contactos reales. La meta es construir una base mínima de seguimiento que permita saber qué ocurrió, en qué etapa está cada oportunidad y qué acción corresponde después.

Usa exclusivamente información ficticia. No escribas contraseñas, datos de pago, documentos de identidad, antecedentes sensibles ni conversaciones completas. Una organización debe definir propósito, acceso, conservación y herramienta autorizada antes de registrar información personal.

## Resultados de aprendizaje

Al finalizar podrás:

1. explicar la diferencia entre un CRM y las herramientas que lo rodean;
2. registrar oportunidades ficticias con una estructura común;
3. usar las seis etapas aprobadas sin inventar estados ambiguos;
4. definir un próximo paso con fecha y responsable;
5. ordenar y filtrar la base para localizar seguimientos pendientes;
6. dibujar un ecosistema digital sin afirmar que existen integraciones no probadas.

## 1. Un CRM es un sistema de seguimiento

CRM significa gestión de relaciones con clientes. En este curso, cada fila representa una oportunidad ficticia; cada etapa describe un hecho observable; y cada próximo paso indica una acción concreta, una fecha y una persona o rol responsable.

El CRM no reemplaza la conversación ni toma decisiones por el equipo. Tampoco tiene que ser una plataforma compleja para enseñar la lógica. La hoja del workbook funciona como fuente de verdad del ejercicio: allí se actualizan la etapa, la fecha próxima y el próximo paso.

El **ecosistema digital** es el conjunto de canales y herramientas que pueden crear, consultar o utilizar esa información. Por ejemplo, una consulta podría llegar desde un formulario; el equipo podría registrarla en el CRM; una persona podría realizar el próximo paso; y un reporte podría resumir resultados. Dibujar esas flechas no significa que las herramientas ya estén conectadas.

### Regla de trazabilidad

Cada dato debe tener una fuente de verdad. Evita mantener etapas o fechas distintas en varias copias. Las conversaciones permanecen en el canal autorizado; el CRM guarda solo el contexto mínimo necesario para el seguimiento.

## 2. Los diez campos de la hoja `2 CRM`

Usa exactamente estas columnas:

| Campo | Qué registra | Criterio de calidad |
|---|---|---|
| Lead ID | Identificador ficticio único | No vacío y no reutilizado |
| Nombre ficticio | Nombre inventado para reconocer el caso | No corresponde a una persona real |
| Origen | Canal de llegada | Fuente reconocible y consistente |
| Interés | Necesidad resumida | Breve, clara y sin datos sensibles |
| Etapa | Estado comercial observable | Uno de los seis valores aprobados |
| Último contacto | Referencia temporal más reciente | Mismo formato en todas las filas |
| Próximo paso | Acción que debe ocurrir | Comienza con un verbo concreto |
| Fecha próxima | Momento de revisión | Definida cuando el caso sigue activo |
| Responsable | Persona o rol que comprobará el avance | Un responsable por fila |
| Observación | Contexto mínimo necesario | Sin secretos ni conversaciones completas |

No agregues campos por costumbre. Si un dato no cambia una decisión ni ayuda al seguimiento, probablemente no pertenece a esta base inicial.

## 3. Las seis etapas aprobadas

La lista desplegable del workbook contiene exactamente estos valores:

| Etapa | Hecho observable |
|---|---|
| Nuevo | El registro ingresó y todavía debe revisarse. |
| Contactado | Ya ocurrió una primera respuesta. |
| Calificado | La necesidad está clara y tiene sentido continuar. |
| Oferta | Se entregó una propuesta o alternativa para evaluar. |
| Cerrado | El proceso terminó con el resultado previsto. |
| Descartado | Se decidió no continuar. |

Evita estados subjetivos como “interesante”, “casi listo” o “ver después”. Dos personas deberían poder revisar la evidencia y clasificar el caso de forma parecida.

El workbook no incluye una etapa “En pausa”. Si un caso debe revisarse después, conserva la etapa que describe el último hecho, anota el motivo mínimo en `Observación` y define una `Fecha próxima`. El paso del tiempo no cambia una etapa automáticamente; esa decisión conserva revisión humana.

## 4. Actividad guiada: cinco oportunidades ficticias

Abre la hoja `2 CRM` del workbook y completa cinco filas. Varía el origen, el interés y la etapa para que la base sirva para practicar filtros. Puedes usar este ejemplo como punto de partida, pero cambia al menos dos situaciones para demostrar comprensión.

| Lead ID | Nombre ficticio | Origen | Interés | Etapa | Último contacto | Próximo paso | Fecha próxima | Responsable | Observación |

| DEMO-001 | Andrea Ejemplo | Formulario | Curso para equipo | Nuevo | 2026-09-20 | Revisar datos mínimos | 2026-09-23 | Admisiones | Caso inventado |

### Revisión fila por fila

Comprueba lo siguiente:

- el `Lead ID` es único;
- el nombre y la situación son ficticios;
- la etapa pertenece a la lista aprobada;
- el próximo paso comienza con un verbo;
- la fecha permite saber cuándo revisar;
- existe una persona o rol responsable;
- la observación contiene solo contexto mínimo.

`Hacer seguimiento` es demasiado amplio. Prefiere acciones verificables como `Revisar datos mínimos`, `Preparar borrador de respuesta` o `Confirmar alcance de práctica`.

## 5. Usa la base como vista de control

El workbook no incorpora un dashboard comercial automático. La vista de control de esta actividad consiste en ordenar y filtrar las filas.

Realiza estas tres pruebas:

1. filtra una etapa y cuenta manualmente los registros visibles;
2. ordena por `Fecha próxima` para encontrar qué revisar primero;
3. filtra por `Responsable` para comprobar quién debe revisar cada caso.

Con cinco registros ficticios no corresponde afirmar tasas de conversión, ventas proyectadas ni beneficios económicos. Un indicador futuro deberá permitir volver a las filas que lo originaron.

## 6. Dibuja el ecosistema digital

En una hoja aparte dibuja esta secuencia:

**Canal de entrada → CRM → Responsable → Próximo paso → Resultado**

Debajo de cada elemento escribe:

- qué información se crea allí;
- dónde se actualiza;
- quién puede revisarla;
- qué salida produce;
- qué ocurriría si la conexión fallara.

Marca cada flecha como `manual`, `posible` o `probada`. En este ejercicio todas deben permanecer `manual` o `posible`: no se ha conectado ningún servicio. Una automatización futura puede copiar datos o generar recordatorios, pero necesita validación, registro de errores y una salida humana antes de operar con información real.

## 8. Quiz de comprobación

Selecciona una respuesta por pregunta. Puntaje sugerido de aprobación: **5 de 6**.

1. ¿Qué representa cada fila en el ejercicio?
   - A. Una campaña completa.
   - B. Una oportunidad ficticia.
   - C. Una integración automática.

2. ¿Cuál es una etapa válida del workbook?
   - A. Casi listo.
   - B. En pausa.
   - C. Calificado.

3. ¿Cuál es el mejor próximo paso?
   - A. Hacer seguimiento.
   - B. Revisar si la consulta contiene los datos mínimos.
   - C. Resolver pronto.

4. Si un caso debe revisarse más adelante, ¿qué corresponde hacer?
   - A. Inventar la etapa En pausa.
   - B. Borrarlo.
   - C. Conservar la etapa observable y definir fecha próxima.

5. ¿Qué demuestra una flecha en el diagrama del ecosistema?
   - A. Una relación diseñada; no necesariamente una integración activa.
   - B. Que el sistema ya está en producción.
   - C. Que no hace falta revisión humana.

6. ¿Qué información puede usarse en esta práctica?
   - A. Una lista real de clientes.
   - B. Credenciales de prueba compartidas.
   - C. Datos completamente ficticios.

### Respuestas

1. B — cada fila representa una oportunidad ficticia.  
2. C — `Calificado` pertenece a la lista aprobada.  
3. B — contiene un verbo y un resultado comprobable.  
4. C — el workbook no incluye `En pausa`.  
5. A — el diagrama describe el recorrido, no prueba una conexión.  
6. C — el ejercicio se realiza exclusivamente con datos ficticios.
